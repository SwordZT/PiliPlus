# 局域网遥控模式

入口：**设置 → 遥控模式**。两端都运行 PiliPlus，连接同一 Wi-Fi 或手机热点，且网络允许设备互访。

1. 在 Pad 上选择「作为被控端」，保持 App 在前台。
2. 在手机上输入 Pad 显示的 IPv4 地址（含端口）和六位配对码，点击「连接 Pad」。无需服务端或 B 站账号共享。
3. 手机返回主页正常选片，详情页的播放器区域显示遥控面板；简介、评论、选集仍在手机上使用。进入详情页是否立即播放，沿用手机的自动播放设置。
4. Pad 配对后显示等待提示；选片后仅显示视频、弹幕和字幕，不显示本地播放控件。

遥控面板支持播放/暂停、拖动进度、快进/快退十秒、音量、倍速、弹幕开关；显示的进度和音量来自被控端。Pad 自行获取视频资源，使用 Pad 自己的账号和播放权限。普通视频、番剧和课程沿用现有详情页参数；本地离线文件不支持遥控播放，手机会显示提示而不会在本地播放。

断线后 Pad 暂停，手机显示断线提示，不切换到本地播放。返回遥控模式入口可重新配对或退出。Pad 等待页/播放页的系统返回键退出被控模式；手机的「退出遥控模式」返回主页，后续选片恢复正常播放。

## 通信与权限

- IPv4 局域网直连 WebSocket，使用系统分配的端口；不访问公共地址，不依赖云端中继或设备发现。
- 一次仅接受一个遥控端。配对码十分钟有效，断线后重新生成；连续五次错误配对会限流三十秒。配对信息不持久化。
- 指令包含请求编号与回复；播放状态每 500ms 同步。后续选片替换接收端视频页；已失效的选片请求不能启动旧视频。
- Android 17+ 请求本地网络权限；iOS 使用本地网络权限说明。拒绝权限或 Wi-Fi 隔离设备时不能配对。
- 被控端在启用模式时保持屏幕唤醒；本功能不承诺后台唤醒或跨网络连接。

## 开发验证

```sh
flutter test --no-pub test/remote
flutter analyze --no-pub
flutter build linux --debug --no-pub
```

协议测试使用真实回环 WebSocket，覆盖配对验证、单遥控端、指令顺序、状态同步、接收端错误、断线中的指令、配对限流和非法参数。界面测试覆盖手机面板、断线禁用、手动播放、被控等待页以及新详情页构建时的选片请求，共十项。Linux 原生实例已检查配对、连续选片、音量、弹幕、倍速、暂停与进度指令调用。手机与 Pad 的网络权限、系统音量和真实 B 站视频播放仍需双设备验收。
